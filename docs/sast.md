# Статический анализ безопасности

## Команда и область проверки

`make sast` запускает закреплённый Bandit 1.9.4. Анализируются Python-файлы в `src`, `scripts`, `migrations`, а также `tests/configuration.py`, используемый сценарием первоначальной настройки тестовой БД. Все уровни серьёзности и уверенности включены. Любое замечание завершает команду с ненулевым кодом; дополнительная проверка JSON-отчёта также запрещает ошибки анализа и непроверенные файлы.

Результат сохраняется в `reports/sast.json`. PostgreSQL и запуск приложения не требуются. `make verify` выполняет SAST вместе с Ruff, тестами, порогом покрытия и проверкой контрольных мутаций.

Bandit проверяет Python AST. JavaScript/HTML и уязвимости установленных библиотек этой командой не анализируются. Тестовые сценарии проверяются Ruff и pytest; их `assert` и демонстрационные входные данные не являются кодом приложения. Тестовая конфигурация включена в SAST отдельно, поскольку используется служебным сценарием.

## Разбор первоначальных замечаний

| Правило | Решение и обоснование |
| --- | --- |
| B405, B314: небезопасный разбор XML | `xml.etree.ElementTree` заменён на `defusedxml.ElementTree`. Версия defusedxml 0.7.1 закреплена в dev-зависимостях и lock-файле. |
| B404: импорт subprocess | Точечный `# nosec B404` в `scripts/check_mutations.py`. Сценарию нужен запуск локального pytest для каждой временной копии кода. Импорт сам по себе не запускает команду. |
| B603: subprocess без оболочки | Точечный `# nosec B603` на вызове в том же файле. Используется `sys.executable`, фиксированный модуль pytest и список аргументов; `shell=False` задан явно. Путь отчёта и рабочая директория создаются сценарием через `TemporaryDirectory`. В аргументы не передаются пользовательский ввод, HTTP-параметры или команда из окружения. Запуск тестов проверяемого проекта является назначением сценария. |
| B404, B603: запуск pg_dump/pg_restore | Два точечных исключения в `scripts/backup.py`. Исполняемые файлы выбираются только из фиксированных имён pg_dump/pg_restore через PATH; оболочка отключена. Параметры подключения и абсолютный путь архива передаются отдельными аргументами, пароль — только через окружение. Запуск системных утилит является назначением команд копирования; содержимое архива должно происходить из доверенного источника. |

При изменении команды, происхождения аргументов или включении оболочки обоснование B603 необходимо пересмотреть. Глобальные `skips`, baseline и `--exit-zero` не используются. Новые исключения требуют обоснования в Issue/PR согласно правилам README.

## Контроль работоспособности

Во временную копию проверяемого каталога добавляется файл с `eval(input())`: `make sast` должен завершиться с ошибкой, а JSON-отчёт содержать B307. Отдельный контроль с синтаксически некорректным Python-файлом должен также завершиться с ошибкой и записать ошибку анализа в отчёт. Контрольные файлы не добавляются в репозиторий.

## Проверка образа ЛР4

В scripts/check_container_image.py B404/B603 обоснованы запуском только Docker CLI, найденного через shutil.which, с фиксированными командами и списком аргументов без shell. Секреты передаются в память проверяющего процесса из JSON через stdin; не передаются в argv и не выводятся. docker image save читается потоком без записи слоёв на диск.

В scripts/container_check.py B404/B603 относятся к единому запуску доверенного Docker CLI (shutil.which, список аргументов, shell=False). B310 относится к urllib.request.urlopen для URL, сформированного самим тестом из 127.0.0.1 и проверенного числового порта. Runtime-секреты не передаются в argv.
