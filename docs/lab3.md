| 8. Не менее трёх миграций | Четыре последовательные ревизии Alembic |

| 12. Восстановление повреждённых данных | `make check-backup`: изменение/удаление записей и точное восстановление |
| 13. Единый проверочный контур | `make verify` запускает все обязательные локальные проверки |
| 14. Запрет ослабления | README: пропуски тестов, снижение порогов и исключения требуют обоснования; [исключения SAST](sast.md) документированы |
| 15. Функциональное изменение через verify | Причина отклонения (Issue #24, PR #25) проверена через verify; новые команды копирования (Issue #26) проходят итоговый полный verify до коммитов |

Таблица сверена с заданием ЛР3 и [общими требованиями к лабораторным работам](general-lab-requirements.md).

## Общие требования

| Требование | Состояние для ЛР3 |
| --- | --- |
| Результаты в одном Git-репозитории | Код, миграции, команды, тесты и документация хранятся в auctions; локальные копии БД, секреты и генерируемые отчёты исключены из Git |
| Новая функция через задачу, ветку и PR | Блоки ЛР3 связаны с Issue и оформлены отдельными ветками/PR; новая причина отклонения — Issue #24, PR #25 |
| Обязательные локальные команды | Makefile и README; единый обязательный `make verify` |
| Запрет ослабления проверок | Правила README; порог 80%, анализаторы и тесты включены; исключения SAST имеют обоснования |
| Критические файлы видимы и отдельно проверяются | Их изменения включены в PR; README требует отдельной проверки Makefile, pyproject.toml, uv.lock, миграций, .gitignore и конфигурации |
| Студент понимает и объясняет решения | Назначение проверок описано ниже; понимание подтверждает студент на защите |
| Живая демонстрация и контрольное изменение/отказ | Подготовлены команды мутаций, миграций и восстановления; живую демонстрацию нужно выполнить на защите |

В общих требованиях CI → образ → CD → проверка релиза → наблюдение описывают процесс семестрового проекта. В тексте текущей ЛР3 требуется локальный проверочный контур; на этапе ЛР3 CI/CD и контейнерный образ не реализовывались; контейнеризация и проверка CI добавлены в [ЛР4](lab4.md). `make up`, `make down`, `make container-check` перечислены в рекомендуемом интерфейсе и не входят в обязательные пункты ЛР3. Эти команды добавлены отдельными изменениями ЛР4.

Итоговый проверенный результат блока копирования: 139 тестов, совокупное покрытие 90,03%, SAST, три контрольные мутации, миграции и восстановление прошли. Результаты зафиксированы в PR #27; актуальные отчёты воспроизводятся через `make verify`.

## Что объяснять на защите

| Этап make verify | Назначение |
| --- | --- |
| quality | Проверить согласованность lock-файла, форматирование и правила Ruff |
| sast | Найти замечания безопасности Python; запретить ошибки анализа; сформировать JSON |
| test | Подготовить отдельную тестовую БД, выполнить unit/API/DB-тесты и порог покрытия; сформировать JUnit/HTML/XML |
| test-mutations | Подтвердить обнаружение трёх контрольных подмен основной логики во временной копии |
| check-migrations | Проверить чистую БД, последовательное обновление с сохранением данных и соответствие моделям |
| check-backup | Проверить копирование, намеренное повреждение, восстановление и откат повреждённого архива |

Для демонстрации преподавателю доступны отдельные `make test-mutations`, `make check-migrations`, `make check-backup`. Локальные результаты хранятся в `reports/`; полный verify обязателен перед включением любого изменения в main.
