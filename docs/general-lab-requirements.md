# Общие требования к лабораторным работам

Текст предоставленного преподавателем файла «треования к лабораторным работам.txt».

В течение семестра команда из 1-3 человек разрабатывает и сопровождает собственное приложение. Оценивается не только работоспособность исходного кода, но и автоматизация процесса, в рамках которого изменение создается, проверяется, собирается, доставляется и эксплуатируется.
Любое изменение рассматривается как потенциально ошибочное независимо от того, было ли оно написано студентом, другим разработчиком или создано с использованием средств автоматической генерации кода. До включения в основную ветку и выпуска оно должно пройти заранее определенные автоматические и организационные проверки. 

задача → изменение кода → локальные проверки → Git → CI → образ → CD → проверка релиза → наблюдение
 
Ни один способ создания кода не освобождает изменение от обязательных проверок.


Общие требования ко всем лабораторным работам
·       Все результаты хранятся в одном Git-репозитории.
·       Каждая новая функция выполняется через задачу, отдельную ветку и запрос на слияние.
·       В репозитории определены обязательные команды локальной проверки проекта.
·       Запрещается удалять тесты, отключать анализаторы, снижать пороги качества и ослаблять CI только ради прохождения проверки.
·       Изменения критических файлов приемки должны быть видимы в запросе на слияние и отдельно проверяться.
·       Студент обязан понимать и объяснять все файлы, команды и решения проекта.
·       Финальная приемка всегда включает живую демонстрацию и контрольное изменение или отказ.


Рекомендуемый общий командный интерфейс проекта
make setup    	# первоначальная настройка
make run      	# локальный запуск
make test     	# автоматические тесты
make quality  	# форматирование и статический анализ
make migrate  	# применение миграций
make backup   	# создание резервной копии
make restore  	# восстановление резервной копии
make verify   	# полный набор локальных проверок
make up       	# запуск контейнерного окружения
make down     	# остановка окружения
make container-check
